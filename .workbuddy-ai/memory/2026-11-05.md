## 新增「章节目录 + 阅读进度」

需求：自动识别章节，并记住每篇读到哪一页（先评估、后执行，范围严格限定）。

实现（无新增依赖，`ArticleRecord` 不变，老数据零迁移）：
- 新增 `src/lib/chapters.ts`：从**已分页的 PageUnit** 识别章节，只认显式标记（markdown 标题、`Chapter 1`/`CHAPTER IV`/`Part II`/`Prologue`、`第1章`/`第十二回`/`楔子`），并排除句末标点与超长行。**刻意不做「全大写短行即章节」**：`老人与海.txt` 扉页的 `THE OLD MAN`/`THE SEA` 会变假章节。
- 关键决策：章节**不参与分页**（不把 paragraph 提升成 heading、不改 blocks），因此页码、旧书签、翻译缓存键 `unit.index:chars` 全都不变。副作用是章节标题只能靠 CSS 加粗，不改变版式。
- `currentChapter(chapters, unitIndex)` 用**本页第一个块的序号**定位，而不是页码——一章可能从页中间开始，按页码会取到后一章。
- 新增 `src/lib/progress.ts`：`data/users/<id>/progress.json`（`{version:1, articles:{id:{page,totalPages,updatedAt}}}`），读-改-写整体按 userId 串行（`queues`），同一页重复渲染跳过落盘，文件损坏按无进度处理。
- 阅读页：无 `?page` 且 `autoResume` 时 302 到上次页；`?page=1` 或「从头开始」按钮重读。**页码链接必须一律带 `?page=`（含第 1 页）**，否则点「1」回到无参数地址会被自动续读弹回——`pageHref` 与 `client/reader/pager.ts` 都改了。
- 列表页：`读到 N/M 页` + 进度条，卡片直链上次页；仅 `totalPages > 1` 才显示（单页文章显示「可阅读」，否则是噪音）。
- `deleteArticle()` 顺手 `clearArticleProgress()`。
- `site.ts` 新增 `reader: { chapters, rememberProgress, autoResume, chapterTitleMaxLen }`。

验证：`astro check` 0 错误；`npm test` 75 条全通过（62 + 13 新增）；`npm run build` 通过；临时 DATA_DIR + 4401 实测：3 章 6 页文章目录命中、第 5 页「当前：Chapter 3 The End」、列表 `读到 5/6 页`、无参数 302 到 `?page=5`、`?page=1` 覆盖进度、DELETE 后 progress.json 里对应键消失、`/zh` 单页文章显示「可阅读」。临时目录已删，未污染真实 data/。

## 桌面版：Electron 启动器 + 单文件 exe

需求：把站点打包成一个 exe，界面里设端口等参数，能启动 / 关闭服务。

做法（`desktop/`，独立 package.json，不污染主项目依赖，Docker 构建不受影响）：
- `scripts/build-runtime.mjs`：跑 astro build → **esbuild 把 `dist/server/entry.mjs` 打成单文件**（1.3MB）→ 复制 `dist/client` → 复制 `data/dict.db` 作种子。运行时总共 7.2MB，**完全不需要 node_modules**（原方案要带 150MB+ 依赖）。
- esbuild 关键参数：`--bundle --platform=node --format=esm --external:node:*` + **banner 注入 createRequire/__dirname/__filename**，否则 CJS 依赖（depd/http-errors/send）报 `Dynamic require of "path" is not supported`。
- `main.js`：Electron 主进程，spawn 服务时用 `process.execPath` + `ELECTRON_RUN_AS_NODE=1`（Electron 38.8.6 自带 Node 22.22，**实测支持 node:sqlite**，不用另带 node.exe）。
- 界面：端口 / 局域网开关 / 数据目录 / 管理员账号密码 / 自动开浏览器 / 启动·停止 / 实时日志；配置存 `%APPDATA%\ReadBook\config.json`，数据默认 `%APPDATA%\ReadBook\data`，首启自动铺词库。
- `app.setName('ReadBook')` 必须写在最前，否则 userData 取 package.json 的 name（变成 `%APPDATA%\readbook-desktop`）。
- 产物 `desktop/release/ReadBook-1.0.0-portable.exe` 92MB。

踩过的坑（环境相关，很重要）：
- **本机 registry.npmjs.org 被墙**，`npm install` 会卡死十几分钟无输出。`npm config set --location project` 没生成 .npmrc，必须手写 `desktop/.npmrc`：registry + electron_mirror + electron_builder_binaries_mirror 全指 npmmirror。改对后 51 秒装完。
- **WorkBuddy 的 shell 环境里有 `ELECTRON_RUN_AS_NODE=1`**，直接 spawn electron.exe 会当 Node 跑，报 `app.isPackaged of undefined`。启动 GUI 时必须从 env 里删掉这个变量。
- **沙箱的 safe-delete 钩子会拦住删除**：`rm -rf` / `Remove-Item` / `rmdir` 都走 genie-trash，对 `release/win-unpacked` 一直失败，导致 electron-builder 二次打包报 `[safe-delete] 操作失败`。绕过办法：换输出目录 `--config.directories.output=build-tmp` 打包，再把 exe 拷回 release。用户自己在普通 shell 里跑不受影响。
- 打包后 `release/win-unpacked/resources/app.asar` 被某进程长期占用（找不到持有者），目录删不掉，只剩 32KB；重启后清理即可。

验证：dev 模式与 exe 都跑了一遍 CDP 驱动的端到端（改端口→启动→健康检查 200/login 200/CSS 200→停止→端口不再响应），截图确认界面排版。
