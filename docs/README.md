# 文档索引

本目录存放项目的四份配套文档。根目录的 [`../README.md`](../README.md) 是入口（功能说明 + 开发 + 部署命令），这里放的是「展开看」的部分。

## 按问题找文档

| 我想知道 | 看这份 | 更新时机 |
|---|---|---|
| 这个站**应该**有什么功能、某条需求做到哪一步了 | [需求确认单.md](需求确认单.md) | 需求变更时；功能上线时回写实际口径 |
| 怎么部署到服务器 / Docker、怎么备份、怎么排查故障 | [部署手册.md](部署手册.md) | 部署流程、环境变量、容器行为变化时 |
| 怎么打 Windows 单文件 exe、打包报错怎么办 | [打包教程.md](打包教程.md) | 打包流程、Electron 版本、产物结构变化时 |
| 最近一轮测试测了什么、发现并修了什么、哪些没测 | [测试报告.md](测试报告.md) | 每轮完整测试后重写为快照（**不随小改更新**） |

## 各文档定位

- **[需求确认单.md](需求确认单.md)** — 需求的**权威来源**。回答「应该有什么」，不回答「现在有什么」。功能点按模块列出，文末有变更记录（日期 / 改了什么 / 为什么）。代码与它冲突时以代码为准，并把文档改回来。
- **[部署手册.md](部署手册.md)** — 面向运维：环境变量、数据持久化与备份、反向代理与 HTTPS、账号管理、资源限制、故障排查、上线检查清单。含实测数据（镜像体积、内存占用、容器内与宿主机的行为差异）。
- **[打包教程.md](打包教程.md)** — 面向要重新打 exe 的人：前置条件、四个构建命令的区别、目录结构、esbuild 单文件 + banner 原理、日常改动对照表、自定义（端口 / 图标 / 版本 / 安装版）、自验清单、常见报错、与 Docker 版的数据迁移。
- **[测试报告.md](测试报告.md)** — **阶段性快照**，记录某一轮的测试结论与可复现命令输出，不追求实时。引用它里的数字时先确认日期。

## 约定

1. **只有根 README 是入口**，其余文档都从根 README 的「文档索引」或本文件进来。
2. 文档之间互链一律用**相对路径**（同目录直接写文件名，指根目录写 `../README.md`）。
3. 改代码要同步文档，并在对应文档的变更记录表**追加**一行（日期 / 改了什么 / 为什么）；不重写历史行。
4. 截图、测试数据、临时验证产物不进本目录。
